Lesson 6 · 20 min

Queues, resuming, and collisions between sessions

A queue in folders survives a crash: what was running goes back to the entrada. But the same resume that saves one copy tramples the other when two run in the same folder. In this lesson you interrupt and resume a queue, trigger the collision with numbers, lock with flock, and watch the collision guard ask before editing.

Start the lesson

In this lesson you will

  1. 1The states entrada, rodando, feito, and falhou
  2. 2Resuming: at least once, never exactly once
  3. 3Two copies in the same folder: each task runs twice
  4. 4flock and the runtime's collision guard

Goal: interrupt and resume a queue, trigger the collision of two queues in the same folder, and lock with flock and with the collision guard.

03 · Rehearsal: resume, collision and flock

A FAKE claude on the PATH logs each run. Counting the log lines shows how many times each task ran.

Terminal · no-quota rehearsal
cd ~/jornada-agentes                      # git clone https://github.com/inematds/jornada-agentes.git ~/jornada-agentes
E=${TMPDIR:-/tmp}/ensaio-multi/fila; rm -rf $E && mkdir -p $E/bin
cat > $E/bin/claude <<'SH'
#!/usr/bin/env bash
# FAKE claude: logs who ran what, takes 1 s and answers (no model is called)
echo "$PPID $2" >> "${E_LOG:?}"; sleep 1; echo "resposta para: $2"
SH
chmod +x $E/bin/claude; export PATH=$E/bin:$PATH E_LOG=$E/execucoes.log
nova_fila() { rm -rf $E/fila $E_LOG; mkdir -p $E/fila/entrada; for i in 1 2 3 4; do echo "tarefa $i" > $E/fila/entrada/0$i.md; done; }
F=./ferramentas/fila-caseira.sh

echo "## 1) roda e é interrompida no meio"
nova_fila; timeout -s INT 2.5 $F $E/fila
echo "rodando: $(ls $E/fila/rodando) · feito: $(ls $E/fila/feito | tr '\n' ' ')"
echo "## 2) roda de novo: retoma"
$F $E/fila | tail -1
echo "execuções: $(wc -l < $E_LOG) para 4 tarefas"

echo "## 3) duas filas na mesma pasta, ao mesmo tempo"
nova_fila; $F $E/fila > $E/a.log 2>&1 & $F $E/fila > $E/b.log 2>&1 & wait
echo "execuções: $(wc -l < $E_LOG) para 4 tarefas · repetidas: $(cut -d' ' -f2- $E_LOG | sort | uniq -d | tr '\n' ' ')"

echo "## 4) a mesma coisa com flock"
nova_fila; flock -n $E/fila.lock $F $E/fila > $E/a.log 2>&1 &
sleep 0.3; flock -n $E/fila.lock $F $E/fila || echo "outra fila já roda nesta pasta (saída $?)"; wait
echo "execuções: $(wc -l < $E_LOG) para 4 tarefas"

Run three times, same result. In 2, task 3 ran twice (interrupted and resumed): the task has to survive running again. In 3, all four ran twice. In 4, the second copy never even started.

The log of one of the two copies from run 3 (path shortened to $E):

→ 01.md
rm: cannot remove '$E/fila/fila/rodando/01.md': No such file or directory
  feito
mv: cannot stat '$E/fila/fila/entrada/02.md': No such file or directory
→ 02.md
(…)

The mv fails because the other copy already took the file, but the script carries on and runs the task anyway, with the file the other copy moved to rodando/. And one copy's resume sends back to the input what the other is running. It is not a bug in an agent: the script was built for a single copy, and the lock is what guarantees that.

04 · Sessions that edit the same file: the collision guard

The training project ships colisao.mjs, a hook that logs who edited each file and asks before another session edits it. Here, only the detection; the hook as a guard is course 4.

Terminal · no-quota rehearsal (two sessions faked by the session_id)
cd ~/treino-multi
export INEMA_RUNTIME_ESTADO=${TMPDIR:-/tmp}/ensaio-multi/colisao; rm -rf $INEMA_RUNTIME_ESTADO
G=runtime/mods/runtime-guarda/hooks/colisao.mjs
j() { printf '{"session_id":"%s","cwd":"%s","tool_input":{"file_path":"notas.md"}}' "$1" "$PWD"; }
echo "rascunho" > notas.md
j sessao-AAAAAAAA | node $G pos                      # session A just edited notas.md
echo "## A quer editar de novo"; j sessao-AAAAAAAA | node $G pre; echo "(saída $?)"
echo "## B quer editar o mesmo arquivo"; j sessao-BBBBBBBB | node $G pre; echo; echo "(saída $?)"
Example from the repository
## A quer editar de novo
(saída 0)
## B quer editar o mesmo arquivo
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"Guarda de colisão: Outra sessão (sessao-A) editou notas.md agora há pouco. Seguir mesmo assim, usar outra cópia (worktree) ou cancelar?"}}
(saída 0)

The same session passes silently. The other one gets "permissionDecision":"ask": Claude Code stops and asks. The default window is 30 min (INEMA_COLISAO_MIN). INEMA_RUNTIME_ESTADO sends the log to the rehearsal folder, so it does not mix with your real one.

05 · Collisions that have already happened on this machine

From LESSONS.md of the INEMA monitoring project, with dates. Each one became a one-line rule.

1. Scratchpad

Courses built in parallel by subagents shared the same temporary folder. An image folder with a generic name collided: one agent's script skipped the image because the other's art already existed.

Rule: temporary folder with the task id in its name.

2. Line that moved

In a file shared between sessions (pending items, limits), editing by line number hit the wrong target: another session had inserted at the top.

Rule: match on the line's own text, never on the number.

3. Someone else's commit

An image generated straight into the repo folder was committed by another session that ran git add -A. And portal edits were committed by another session before their time.

Rule: generate outside the repo and prepare the change in an isolated worktree, even when the files are clean.

4. Someone else's process

A test server from another session was killed because it was using the "usual" port.

Rule: pick a truly free port and only kill a process after checking that its folder (/proc/[pid]/cwd) is yours.

08 · In three sentences

Resume repeatsWhat was running goes back to the input; every task has to handle running again.
One queue per folderWithout a lock, two copies run everything twice; flock -n fixes it with one line.
Sessions cross pathsThe guard asks before editing what another session touched; a worktree avoids the question.
