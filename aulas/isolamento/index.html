Aula 5 · 20 min

Isolamento: worktrees e sandboxes

Dois agentes no mesmo checkout não dão erro: um apaga o trabalho do outro em silêncio. Worktree dá a cada um a sua cópia e transforma a perda silenciosa em conflito visível na hora do merge. Sandbox faz o mesmo com as permissões: o revisor lê, mas não grava. Nesta aula você prova as duas coisas sem gastar cota.

Começar a aula

Nesta aula você vai

  1. 1A gravação perdida: dois agentes, um arquivo, nenhum erro
  2. 2Worktree à mão, no claude --worktree, em subagente e no Codex
  3. 3Sandbox read-only e workspace-write do Codex, testados
  4. 4O conflito no merge como sinal bom

Objetivo: dar a cada agente que escreve um worktree próprio e a cada revisor um sandbox só de leitura, e provar a diferença.

01 · Três jeitos de pôr dois agentes no mesmo repositório

Clique em cada um. O ensaio logo abaixo prova os dois primeiros.

Clique em cada bloco do diagrama para ver o que ele faz.

Worktree isola arquivos, não processos: dois worktrees ainda dividem portas, banco local e cota.

02 · Ensaio: a gravação perdida e o worktree

Repositório descartável e dois agentes falsos que leem, esperam 2 s e gravam o arquivo inteiro.

Terminal · ensaio sem cota
E=${TMPDIR:-/tmp}/ensaio-multi/wt; rm -rf $E && mkdir -p $E && cd $E
git init -q repo && cd repo && git config user.name ensaio && git config user.email ensaio@local
printf 'versao = 1\nnome = treino\ncor = azul\n' > config.txt && git add -A && git commit -qm base
# um "agente" lê o arquivo, pensa 2 s e grava o arquivo inteiro (como a ferramenta Write)
agente() { c=$(cat "$1/config.txt"); sleep 2; printf '%s\n' "$c" | sed "$2" > "$1/config.txt"; echo "$3 gravou"; }

echo "## A) dois agentes no MESMO checkout"
agente . 's/azul/verde/' A & agente . 's/versao = 1/versao = 2/' B & wait
cat config.txt
git checkout -q config.txt

echo "## B) um worktree para cada agente"
git worktree add -q ../wt-a -b agente-a && git worktree add -q ../wt-b -b agente-b
agente ../wt-a 's/azul/verde/' A & agente ../wt-b 's/versao = 1/versao = 2/' B & wait
git -C ../wt-a commit -qam "A: cor" && git -C ../wt-b commit -qam "B: versão"
git merge -q agente-a && git merge -q --no-edit agente-b && cat config.txt
git worktree list | wc -l
Exemplo do repositório
## A) dois agentes no MESMO checkout
B gravou
A gravou
versao = 1
nome = treino
cor = verde
## B) um worktree para cada agente
A gravou
B gravou
Auto-merging config.txt
versao = 2
nome = treino
cor = verde
3

Em A, os dois disseram "gravou" e a versão 2 sumiu. Em B, as duas mudanças entraram. A ordem de "A gravou" e "B gravou" varia de uma rodada para outra; o resultado não.

Dois worktrees mudando a MESMA linha (cor roxo × cor preto), capturado no mesmo repositório:

Auto-merging config.txt
CONFLICT (content): Merge conflict in config.txt
Automatic merge failed; fix conflicts and then commit the result.
saída: 1

No checkout único, isso seria uma perda calada. Aqui o git para e mostra. Quem resolve é o orquestrador (ou você), não um dos dois agentes.

03 · Worktree nas ferramentas

Claude Code 2.1.303 e Codex CLI 0.163.0, pelas docs lidas em 19/10/2026.

1. claude --worktree

claude --worktree [nome] cria o worktree em .claude/worktrees/[nome] e abre a sessão lá. Precisa de pelo menos um commit e, no modo interativo, da pasta marcada como confiável (rode claude uma vez nela).

Arquivos ignorados pelo git, como .env, não vão para o worktree; liste-os num .worktreeinclude na raiz para copiar.

PegadinhaHooks com ${CLAUDE_PROJECT_DIR} continuam rodando no checkout principal; o campo cwd do hook é que acompanha o worktree.

2. Subagente

No frontmatter, isolation: worktree dá ao subagente um worktree temporário, que some sozinho se ele não mudar nada.

Atenção: a branch parte do branch padrão, não do HEAD da sua sessão. O que você não commitou não está lá.

3. Sessões e times

Sessão em segundo plano (claude --bg) entra num worktree antes de editar. Agent teams não isolam: divida os arquivos por dono.

Uma limpeza periódica remove worktrees criados pelo Claude que passaram de cleanupPeriodDays e não guardam trabalho.

4. Codex

codex exec --worktree "[pedido]" roda num worktree gerenciado (não combina com resume nem --ephemeral). Na TUI, /worktree.

Sandbox: -s read-only para quem só revisa, -s workspace-write para quem executa. A doc pede para evitar --dangerously-bypass-approvals-and-sandbox fora de uma VM dedicada.

04 · Sandbox por papel, testado sem modelo

codex sandbox roda um comando qualquer com as mesmas regras que o Codex usa nos dele. Não chama modelo.

Terminal · ensaio sem cota
E=${TMPDIR:-/tmp}/ensaio-multi/sbx; rm -rf $E && mkdir -p $E && cd $E
codex sandbox -c sandbox_mode=read-only -- bash -c 'echo x > a.txt 2>/dev/null && echo "read-only: gravou" || echo "read-only: bloqueado na pasta"'
codex sandbox -c sandbox_mode=workspace-write -- bash -c 'echo x > b.txt && echo "workspace-write: gravou na pasta"; echo x > ~/fora-sbx.txt 2>/dev/null && echo "gravou fora" || echo "workspace-write: bloqueado fora da pasta"'
ls; ls ~/fora-sbx.txt 2>&1 | tail -1
Terminal · worktree de verdade no projeto de treino
# terminal 1: abre a sessão já dentro do worktree (não precisa pedir nada)
cd ~/treino-multi && claude --worktree treino-a

# terminal 2, com a sessão aberta:
cd ~/treino-multi && git worktree list | grep -c ".claude/worktrees/treino-a"
git branch --list worktree-treino-a

# terminal 1: /exit (worktree sem mudanças: escolha remover, se perguntar). Depois:
git worktree list | wc -l
Exemplo do repositório
bash: line 1: a.txt: Read-only file system
read-only: bloqueado na pasta
workspace-write: gravou na pasta
bash: line 1: ~/fora-sbx.txt: Read-only file system
workspace-write: bloqueado fora da pasta
b.txt
ls: cannot access '~/fora-sbx.txt': No such file or directory

Edição declarada: o caminho da pasta pessoal aparece como ~. O read-only não gravou nem dentro; o workspace-write gravou b.txt e foi barrado fora.

Worktree parte de um commit. Num git init recém-criado, o claude --worktree sai antes de chamar o modelo (capturado com Claude Code 2.1.303):

Error creating worktree: Failed to resolve base branch "HEAD": git rev-parse returned no commit for HEAD (for example in a new repository, or on a branch without a commit yet), so Claude Code has nothing to base a worktree on. (…)
saída: 1

Faça um commit e rode de novo.

5 min

E11 · Um worktree do Claude Code

10 min

No projeto de treino, abra claude --worktree treino-a num terminal e confira de outro. Ao sair, um worktree limpo é removido (numa sessão com nome, o Claude pergunta antes).

Pronto quando: com a sessão aberta, git worktree list | grep -c ".claude/worktrees/treino-a" → 1 e a branch worktree-treino-a existe; depois de sair, git worktree list | wc -l → 1 (se ficou, git worktree remove .claude/worktrees/treino-a).

07 · Em três frases

Checkout único perdeDois agentes gravando o mesmo arquivo: o último vence e ninguém avisa.
Worktree por escritorCada agente que grava ganha cópia e branch; o merge junta ou mostra o conflito.
Sandbox por papelRevisor em read-only, executor em workspace-write; acesso total só em VM dedicada.
