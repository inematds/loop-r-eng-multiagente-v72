Aula 3 · 20 min

Orquestrador-trabalhadores e fan-out

Fan-out é um orquestrador soltando N trabalhadores sobre itens independentes e juntando só o que importa. Funciona quando cada item cabe num pedido claro, tem teto e devolve uma linha conferível. Nesta aula você roda um fan-out em shell com agente falso, vê o tempo cair e refaz só o item reprovado.

Começar a aula

Nesta aula você vai

  1. 1As formas de fan-out no Claude Code e no shell
  2. 2O pedido de delegação: objetivo, formato, fontes e fronteiras
  3. 3Teto por trabalhador e retorno em arquivo
  4. 4Consolidar pela última linha e refazer só o reprovado

Objetivo: rodar um fan-out com N trabalhadores, teto por item e consolidação curta, refazendo só o item reprovado.

01 · Um fan-out com controle

O orquestrador planeja e junta; os trabalhadores só fazem a sua parte. Clique em cada etapa.

Reprovado? Volta só ele para a lista; os aprovados não são refeitos
Clique em cada bloco do diagrama para ver o que ele faz.

Fan-out de 500 arquivos mecânicos não pede modelo nenhum: é script. Agente entra quando cada item exige julgamento.

02 · As formas de fan-out hoje

Pela doc do Claude Code (Run agents in parallel, lida em 19/10/2026) e pelo Codex CLI 0.163.0.

1. Subagentes

Peça vários subagentes na mesma mensagem. Os resultados voltam para a conversa que os criou.

Para um lote grande e repetível, a doc aponta dynamic workflows (um script que roda muitos subagentes e confronta resultados) e o /batch, que divide uma mudança grande em 5 a 30 subagentes, cada um no seu worktree.

2. Sessões

claude --bg solta uma sessão em segundo plano; claude agents mostra todas numa tela. Antes de editar, a sessão de fundo entra num worktree próprio em .claude/worktrees/.

Cada sessão gasta a sua cota. Junte os resultados por arquivo, numa sessão chefe ou num script.

3. Agent teams

Desligado por padrão (CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1). Um líder e colegas com lista de tarefas e mensagens entre si. Um time por sessão, sem time aninhado, e /resume não restaura colegas em processo.

Colegas não ganham worktree: dois editando o mesmo arquivo sobrescrevem. Divida os arquivos por dono.

4. Shell

Fora da sessão, um xargs -P com claude -p ou codex exec por item. É o que você controla melhor: teto, arquivo de saída, retomada.

É a forma do ensaio abaixo, porque dá para trocar o agente por um script falso.

03 · Fan-out em shell, com ensaio

O AGENTE é qualquer comando que lê o pedido no stdin. Para o ensaio, um script que dorme 2 s e responde.

fanout.sh · salve em ~/treino-multi/
#!/usr/bin/env bash
# fanout.sh — um trabalhador por linha da lista, N ao mesmo tempo, retorno curto em arquivo.
# Uso: fanout.sh <lista.txt> <pasta-saida> [N]
#   AGENTE = comando que lê o pedido no stdin (padrão: claude -p). Para ensaio: um script falso.
#   TETO   = segundos por trabalhador (padrão 600)
set -u
LISTA="${1:?uso: fanout.sh <lista.txt> <pasta-saida> [N]}"; OUT="${2:?pasta de saída}"; N="${3:-3}"
export OUT AGENTE="${AGENTE:-claude -p}" TETO="${TETO:-600}"
mkdir -p "$OUT"

trabalho() {
  item="$1"; nome=$(printf '%s' "$item" | tr -cs 'a-zA-Z0-9' '-' | cut -c1-40)
  if [ -s "$OUT/$nome.md" ] && [ "$(tail -1 "$OUT/$nome.md")" = OK ]; then
    echo "pula $nome (aprovado)"; return 0     # só o reprovado volta
  fi
  printf 'Tarefa: %s\nResponda em no máximo 5 linhas. Última linha: OK, ou FALHA: <motivo>.\n' "$item" \
    | timeout "$TETO" $AGENTE > "$OUT/$nome.tmp" 2>&1
  rc=$?
  if [ $rc -eq 0 ]; then mv "$OUT/$nome.tmp" "$OUT/$nome.md"; echo "feito $nome"
  else mv "$OUT/$nome.tmp" "$OUT/$nome.erro"; echo "erro $nome (rc=$rc)"; fi
}
export -f trabalho

grep -v '^[[:space:]]*$' "$LISTA" | xargs -d '\n' -P "$N" -I{} bash -c 'trabalho "$1"' _ {}

# o orquestrador junta só as últimas linhas: é isso que volta para o contexto dele
for f in "$OUT"/*.md; do [ -e "$f" ] && printf '%s: %s\n' "$(basename "$f" .md)" "$(tail -1 "$f")"; done > "$OUT/../consolidado.txt"
echo "itens: $(grep -cv '^[[:space:]]*$' "$LISTA") · feitos: $(ls "$OUT"/*.md 2>/dev/null | wc -l) · com erro: $(ls "$OUT"/*.erro 2>/dev/null | wc -l) · OK: $(grep -c ': OK$' "$OUT/../consolidado.txt") · FALHA: $(grep -c ': FALHA' "$OUT/../consolidado.txt")"
Terminal · ensaio sem cota (agente falso)
cd ~/treino-multi && chmod +x fanout.sh
E=${TMPDIR:-/tmp}/ensaio-multi/fanout; rm -rf $E && mkdir -p $E

  *quebrado*) printf 'não consegui ler o arquivo\nFALHA: arquivo quebrado\n' ;;

Teto é obrigatório, mas calibrado: rode um item real sozinho, meça e dê folga. Sem teto, um trabalhador travado segura o lote inteiro.

04 · O pedido de delegação

Quando o fan-out é dentro da sessão, o orquestrador é você pedindo. Os quatro campos vêm do post da Anthropic.

Prompt · fan-out com subagentes numa sessão
Divida em subagentes, um por item da lista abaixo, todos na mesma mensagem.
Para cada subagente, escreva:
- Objetivo: <o que este item precisa responder>
- Formato de saída: no máximo 5 linhas; última linha OK ou FALHA: <motivo>; grave em saida/<item>.md
- Fontes e ferramentas: <arquivos ou pastas que pode ler>; não edite nada fora de saida/
- Fronteira: não trate dos outros itens; se depender de outro item, pare e diga qual
Depois, leia só a última linha de cada arquivo e me dê a tabela item → OK/FALHA.
Itens:
<item 1>
<item 2>
<item 3>

05 · Prática

Ensaio primeiro; depois dois itens reais.

E5 · Fan-out com agente falso

10 min

Salve o fanout.sh e rode o ensaio inteiro.

Pronto quando: a rodada com N=1 leva cerca de 10 s e a com N=3 cerca de 4 s; as duas imprimem OK: 4 · FALHA: 1; a terceira imprime quatro linhas pula … (aprovado) e uma feito resumir-docs-quebrado-md.

E6 · Dois itens reais

10 min

Rode o bloco real (ele usa claude -p, pela sua assinatura). Se um item sair FALHA, leia só o arquivo dele e rode o fanout.sh de novo.

Pronto quando: cat real/consolidado.txt mostra 2 linhas, cada uma terminando em OK ou FALHA: …, e ls real/saida/*.erro não acha nada.

07 · Em três frases

Itens congeladosSó entra no fan-out o que não depende de outro item; o resto vai antes ou depois.
Teto e arquivoCada trabalhador com timeout, resultado gravado e última linha OK ou FALHA.
Só o reprovado voltaO orquestrador lê as últimas linhas e reroda só o que falhou.
