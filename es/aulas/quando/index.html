Clase 1 · 15 min

Cuándo NO usar multiagente

Cada agente adicional vuelve a leer el contexto, gasta su propia cuota y necesita ser coordinado. En la mayoría de las tareas de código, un solo agente, o subagentes que devuelven poco, rinde más. En esta clase decides antes de abrir el segundo agente, con una matriz de señales que corre como script.

Empezar la clase

En esta clase vas a

  1. 1Cuánto cuesta un equipo: los números publicados y qué miden
  2. 2Las 6 señales de secuencia y las 7 de paralelo
  3. 3La regla de la diferencia de 2 puntos y el híbrido
  4. 4La matriz como script, con tus tareas

Objetivo: decidir entre un agente, secuencia, paralelo o híbrido según la matriz de señales, antes de abrir el segundo agente.

01 · Antes del segundo agente

Haz clic en cada etapa. La matriz es del kit arquiteto-de-execucao (agenteexecuta).

Haz clic en cada bloque del diagrama para ver qué hace.

La matriz es un punto de partida, no una medición. Evita el reflejo de abrir agentes solo porque se puede.

02 · El costo que no aparece en el pedido

Lo que está publicado, con fecha, y qué mide cada número.

1. Tokens

En el post sobre el sistema de investigación de Anthropic (13/06/2025): los agentes gastan cerca de 4× los tokens de un chat, y los sistemas multiagente cerca de 15×. Los datos son de ellos, en un producto de investigación.

La doc de agent teams de Claude Code dice lo mismo sin número: un equipo usa significativamente más tokens que una sesión, y el gasto crece con cada compañero activo.

2. Ganancia

En el mismo post, un líder Opus 4 con subagentes Sonnet 4 superó a Opus 4 solo en un 90,2% en su evaluación interna de investigación, en preguntas de amplitud (muchas direcciones independientes).

El propio post avisa: la mayoría de las tareas de código tienen menos partes paralelizables que la investigación, y los agentes todavía coordinan mal en tiempo real. No hay ninguna medición de este curso que transfiera esa ganancia a tu código.

3. Contexto

La matriz del arquiteto-de-execucao muestra la cuenta (ejemplo ilustrativo, no medido): tres agentes que leen 50 mil de contexto y trabajan 20 mil cada uno suman 210 mil; un agente que reaprovecha el contexto hace lo mismo con 110 mil.

El ahorro viene de no repetir la preparación. El paralelo vale la pena cuando cada tarea tiene contexto pequeño.

4. Límites

Ningún subagente sin tarea, entrada y salida explícitas; como máximo un nivel de delegación, salvo necesidad clara; dos intentos por ítem antes de replantear; no reprocesar un ítem aprobado.

El trabajo mecánico (convertir, renderizar, correr tests) va a un script, no a un agente.

03 · La matriz como script

Escribe las señales de cada tarea en un archivo; el script suma y decide. Nada de modelo: corre gratis.

# decide.py — matriz de decisión del arquiteto-de-execucao (inematds/agenteexecuta), en código
# Uso: python3 decide.py tarefas.txt
# tarefas.txt: un bloque por tarea; "# nome" abre el bloque; después, un código por línea:
#   S1..S6 = señales de secuencia, P1..P7 = señales de paralelo,
#   simples = tarea pequeña (no aplica la matriz), erro-caro = costo de error alto
import sys

SEQ = {"S1": "depende da saída anterior", "S2": "contexto compartilhado grande",
       "S3": "decisões precisam ficar consistentes", "S4": "erro inicial contamina várias tarefas",
       "S5": "juntar versões divergentes sai caro", "S6": "uma etapa ensina a seguinte"}
PAR = {"P1": "tarefas independentes", "P2": "entradas congeladas",
       "P3": "cada saída se valida sozinha", "P4": "trabalho mecânico ou determinístico",
       "P5": "contexto pequeno por tarefa", "P6": "urgência alta", "P7": "há máquina sobrando"}

def decide(nome, cods):
    print(f"# {nome}")
    for c in cods:
        if c not in SEQ and c not in PAR and c not in ("simples", "erro-caro"):
            print(f"aviso: código desconhecido '{c}' (ignorado)")
    if "simples" in cods:
        print("decisão: direto (um agente só, sem matriz)\n")
        return
    s = sum(c in SEQ for c in cods)
    p = sum(c in PAR for c in cods)
    if abs(s - p) >= 2:
        d = "sequencial" if s > p else "paralelo"
    else:
        d = "híbrido"
    print(f"sequência: {s} · paralelo: {p} · diferença: {abs(s - p)}")
    print(f"decisão: {d}")
    if "erro-caro" in cods:
        print("custo de erro alto: planejamento e revisão centralizados")
    print()

nome, cods = None, []
for linha in open(sys.argv[1], encoding="utf-8"):
    linha = linha.strip()
    if linha.startswith("#"):
        if nome:
            decide(nome, cods)
        nome, cods = linha.lstrip("# ").strip(), []
    elif linha:
        cods.append(linha.split()[0])
if nome:
    decide(nome, cods)

La conversión de 500 archivos es paralelo mecánico: un script con varios trabajadores y una revisión por muestreo en el centro (es la clase 3). La investigación de mercado quedó empatada: el primer segmento corre solo, los otros tres en paralelo.

Un código en minúscula no cuenta. El script avisa en lugar de sumar en silencio, y la decisión cambia. Capturado el mismo día:

# migrar o banco
aviso: código desconhecido 's1' (ignorado)
sequência: 1 · paralelo: 1 · diferença: 0
decisão: híbrido

Con S1 correcto, sería secuencia 2 × paralelo 1, todavía híbrido, pero por un motivo que tú elegiste. Verifica con grep -c "^aviso:" decisao.md → 0.

06 · En tres frases

El equipo cuestaCada agente relee el contexto y gasta su propia cuota; publicado: cerca de 15× los tokens de un chat.
Matriz primeroSeñales de secuencia × paralelo; una diferencia de 2 decide, menos que eso es híbrido; el error caro centraliza.
